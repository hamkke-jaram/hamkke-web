# hamkke-web — 함께자람 모바일 웹

부모 앱과 기관 선생님 화면(React 18 · TypeScript · Vite, PWA). 영상 분석은 [hamkke-ai](https://github.com/hamkke-jaram/hamkke-ai) 패키지로 **폰 브라우저 안에서** 하고, 서버([hamkke-api](https://github.com/hamkke-jaram/hamkke-api))에는 지표 JSON만 보낸다. 영상 원본과 소리는 기기 밖으로 나가지 않는다.
보호자가 아이별로 **AI 관찰 기록**에 동의한 경우에만 장면 사진 최대 6장을 AI 서버(hamkke-ai `server/`)로 보내 관찰 기록(글)을 만든다. 아래 [AI 관찰 기록](#ai-관찰-기록) 참고.

> 본 서비스는 의료기기가 아니며 발달 상태를 판단하지 않습니다. 걱정되는 점은 전문의와 상담하세요.

## 실행

```bash
npm install
npm run dev     # http://localhost:5173 (/api → http://localhost:8080, /ai/ → http://localhost:8090 프록시, 처음 분석할 때 분석 도구 약 17MB 내려받음)
```

휴대폰으로 데모 열기(QR): `npm run dev:lan`으로 띄우면 같은 와이파이의 휴대폰이 들어올 데모 주소(`/try`)와 QR 코드가 터미널에 나오고, 앱의 `/qr` 화면에도 같은 QR이 보인다. QR은 데모 입구 `/try`를 가리켜 로그인 없이 예시 데이터로 채운 화면이 열린다(실제 서비스 입구 `/`는 가입·로그인). 배포한 주소가 있으면 `VITE_PUBLIC_URL`을 넣어 빌드하면 `/qr`이 그 주소의 `/try`로 QR을 만든다. http 주소(와이파이 개발 서버)에서는 휴대폰의 실시간 카메라가 열리지 않고, 영상 파일을 골라 기록하는 것은 된다.

백엔드는 hamkke-api에서 `./gradlew bootRun`, AI 서버는 hamkke-ai의 `server/`(8090). AI 서버가 없어도 나머지 기능은 그대로 동작한다.
실시간 카메라(`getUserMedia`)는 HTTPS 또는 localhost에서만 동작한다. 영상 파일을 골라 기록하는 화면은 http에서도 되도록, 보안 연결에서만 있는 `crypto.randomUUID()` 대신 `src/api/uuid.ts`의 `newUuid()`를 쓴다.

## iOS 앱 (`ios/`)

SwiftUI 앱이 이 웹앱을 WKWebView로 띄운다(화면·기능은 웹과 같고, 웹을 고치면 앱도 바뀐다). 앱이 더하는 것: 모찌가 통통 뛰는 시작 화면, 앱 머리줄(화면 제목·뒤로), 아래 탭(홈·가운데 노란 '기록하기'·도움받기·내 정보), 당겨서 새로고침, 누를 때 진동, 화면 왼쪽 끝에서 밀어 뒤로, 서버에 닿지 못했을 때의 안내와 '서버 주소 바꾸기', 내려받은 파일 공유 시트, 실시간 카메라 권한.

```bash
npm run dev:lan                                  # 웹(5173)
(cd ../hamkke-api && sh ./gradlew bootRun)       # API(8080, Java 21)
open ios/HamkkeJaram.xcodeproj                   # Xcode에서 HamkkeJaram 스킴을 시뮬레이터로 실행
```

- 시뮬레이터는 기본 주소 `http://localhost:5173/try`(빌드 설정 `HJ_WEB_URL`, 웹의 QR 데모 입구)로 이 Mac의 개발 서버를 열어 로그인 없이 예시 데이터 화면을 바로 보여 준다(이미 로그인되어 있으면 그 계정의 홈). 실기기는 앱의 ⋯ → '서버 주소 바꾸기'에 Mac의 와이파이 주소만 넣으면 데모(`/try`)가 열리고, 가입·로그인 화면은 주소 끝에 `/login`을 붙인다.
- 웹과 앱의 다리는 `src/native.tsx`: 앱 안에서는 `<html class="ios-app">`로 웹 상단바를 숨기고, 화면 주소·제목(`route`)과 진동(`haptic`)만 앱에 알린다. 앱은 `window.hjNavigate(path)`·`window.hjBack()`으로 화면을 바꾼다.
- **QR 데모(`/try`)**: QR로 들어오면 로그인 없이 데모 보호자 계정 + 예시 아이(콩이) + 지난 4주 예시 기록을 만들어 아이 홈을 연다(`src/pages/TryDemo.tsx`, `seedSampleChild`). 같은 기기로 다시 들어오면 그 데모 계정으로 이어서 연다. 예시 아이의 법정대리인 동의는 시험 데이터라 자동으로 보낸다. 개발 서버, 시연 빌드(`VITE_DEMO_MODE=true`), `VITE_TRY_ENABLED=true` 빌드에만 있다.

## 안드로이드 앱(Capacitor)

같은 React 화면을 안드로이드 앱으로 감싼다(`android/`, `capacitor.config.ts`). 웹 빌드·배포는 바뀌지 않는다.
필요한 것: JDK 21(`JAVA_HOME`), Android SDK(`ANDROID_HOME`, 윈도우는 기본 위치를 스스로 찾음), API 8080·AI 서버 8090.

```bash
npm run android:build                  # 웹 빌드(--mode android) + 앱에 복사(cap sync)
npm run android:apk                    # 디버그 APK → android/app/build/outputs/apk/debug/app-debug.apk
npm run android:install -- emulator-5556   # adb reverse 8080·8090 + 설치 + 앱 열기(기기가 하나면 이름 생략)
```

- 앱 화면은 기기 안 파일(`https://localhost`)에서 열려 프록시가 없다. 앱 빌드만 `.env.android`의 `VITE_API_ORIGIN`·`VITE_AI_ORIGIN`(기본 `http://localhost:8080`·`8090`)으로 `/api`·`/ai` 요청을 보낸다(`src/api/origin.ts`). 웹 빌드에서는 비어 있어 아무 일도 하지 않는다. 다른 주소는 `.env.android.local`에.
- 요청은 Capacitor가 네이티브로 보낸다(`CapacitorHttp`). 그래서 서버에 CORS 설정이 없어도 된다. 평문 http는 디버그 빌드에서 localhost·127.0.0.1·10.0.2.2에만 허용한다(`android/app/src/debug/`).
- 분석 모델(`public/mediapipe`)은 APK 안에 들어가 인터넷 없이 뜬다. 뒤로 가기 버튼은 앱 안 뒤로 가기, 첫 화면에서는 앱을 닫는다.
- Android Studio로 열려면 `npx cap open android`.

## 화면

| 사용자 | 경로 |
|---|---|
| 공통 | `/` 소개 · `/signup` · `/login` · `/support` 상담·기관 안내(로그인 불필요) · `/privacy` · `/terms` 이용약관 요약 · `/account`(이름·비밀번호 바꾸기, 동의 기록, 내 데이터 내려받기, 탈퇴) |
| 부모 | `/p` · `/p/children/new`(법정대리인 동의) · `/p/children/:id`(주간 요약·코칭·지난 카드 다시 보기·선생님 이야기·AI 관찰 기록) · `/p/children/:id/edit`(별칭·생년월 고치기) · `/p/children/:id/records`(기록 목록·한 건씩 지우기) · `/p/children/:id/record`(촬영·분석) · `/p/children/:id/observe`(실시간 카메라) · `/p/children/:id/share`(공유·초대 코드 만들기·목록·취소) |
| 기관 선생님 | `/t`(초대 코드 연결) · `/t/children/:id`(공유된 요약·목표 쓰기·고치기·관찰 메모·AI 관찰 기록·연결 끊기) · `/t/children/:id/observe`(기관에서 관찰 기록하기) |

- **약관 다시 동의**: 로그인 뒤 `GET /me`의 `pendingConsents`가 비어 있지 않으면(약관·개인정보 처리 방침 버전이 바뀜) 다른 화면 대신 '약관 다시 동의' 화면을 보여 준다(`src/pages/Reconsent.tsx`). 항목마다 `POST /me/consents {type, version}`을 보내고 `/me`를 다시 불러 이어서 원래 화면을 보여 준다. 이 동안에도 `/terms` · `/privacy` · `/support` · `/account`(내 데이터 내려받기·탈퇴)는 열 수 있다.
- **비밀번호 바꾸기**: `PUT /me/password`가 돌려준 새 토큰 한 쌍으로 이 기기의 세션을 바꾼다(다른 기기의 로그인은 서버가 끝낸다). 지금 비밀번호가 틀린 401 `INVALID_CREDENTIALS`는 토큰 갱신을 하지 않고 그 칸 아래에 알린다.
- **내 데이터 내려받기**: `GET /me/export`의 JSON을 `hamkke-jaram-export.json` 파일로 이 기기에 저장한다(내용을 콘솔·저장소에 남기지 않는다).
- **목록 '더 보기'**: 기록·코칭 카드·관찰 메모·AI 관찰 기록 목록은 `limit`개씩 받고, '더 보기'를 누르면 마지막 항목 id를 `beforeId`로 보내 이어서 받는다(`src/components/paging.ts`). 같은 항목이 다시 오면(예전 서버) 겹치지 않게 하고 멈춘다.
- **불러오기 실패**: 아이 홈의 카드·목표·메모 등 목록을 못 불러오면 비어 있는 것과 구별되게 '…을 불러오지 못했어요 + 다시 불러오기'를 보여 준다(`loadStateView`).
- **실제 서비스 입구**: 첫 화면(`/`)은 '시작하기'(가입)·'로그인'이고, 로그인이 필요한 화면은 로그인 화면으로 보낸다. QR 데모가 쓰는 '이 기기 계정'(`src/auth/guest.ts`, 무작위 이메일 `…@guest.hamkke.test`·비밀번호를 이 기기 localStorage `hj.guest`에만 둠)은 `/try`에서만 만든다. 그 계정으로 들어온 경우 내 정보에서는 이메일·비밀번호 바꾸기를 보이지 않고, 탈퇴는 저장된 비밀번호로 한다.
- **보호자·선생님 이야기**: `/p/children/:id/talk`(보호자) · `/t/children/:id/talk`(선생님). 아이에 대해 짧은 이야기를 주고받고, 선생님 관찰 메모가 같은 흐름에 보이며 '이 메모에 답하기'로 그 메모에 답한다(`src/talk/`, API는 hamkke-api `/children/{id}/messages`). 3초마다 새 이야기만 받아 와 상대가 보낸 것이 곧 나타나고, 아이 홈의 '선생님 이야기'·선생님의 아이 화면에 안 읽은 수 배지가 붙는다. 보이는 동안 받은 이야기는 읽음으로 표시한다.
- **보호자 ↔ 선생님 함께 보기(시연)**: `/demo/duo`(개발·시연 빌드). '시연 준비하기'가 시연 보호자·아이·기록·선생님을 만들어 연결하고, 두 휴대폰을 나란히 띄운다. 두 화면은 서로 다른 주소(localhost · 127.0.0.1)로 열어 한 브라우저에서 두 계정이 함께 로그인되고, 시연 영상은 이 화면을 녹화하면 된다. 개발 서버는 `/api`로 넘길 때 Origin을 빼서 와이파이 주소·127.0.0.1에서도 쓰기 요청이 막히지 않는다(`vite.config.ts`).
- **움직이는 캐릭터**: 화면 아래에서 모찌가 통통 뛰어다닌다(`src/components/MochiBuddy.tsx`, 움직임 계산은 `buddyPhysics.ts`). 끌어서 옮기거나 던질 수 있고, 누르면 폴짝 뛰며 하트가 뜬다. 화면이 바뀌면 한 번 뛰고, 선생님에게는 선생님 모찌가 다닌다. 눈을 깜빡이고 가는 쪽을 쳐다보며(`BuddyFace.tsx`가 그림 위에 눈을 다시 그린다), 뛰기 전에 웅크리고, 착지하면 먼지가 일고, 가끔 춤추거나 존다(Zzz, 누르면 놀라 깸). 들고 있으면 진자처럼 흔들리고 세게 던지면 별이 돌며 어지러워한다. 버튼·링크 위에 서 있는 동안은 누름이 아래 버튼으로 통과하고, 쉬는 중이면 비켜 간다(비킬 곳이 없으면 가장자리로). 입력칸에 글을 쓰는 동안과 촬영·실시간 카메라 화면, 약관 다시 동의 중에는 나오지 않는다. 화면 속 캐릭터 그림(`.mascot`)도 숨 쉬듯 말랑거린다. '내 정보 → 화면 설정 → 움직이는 캐릭터'로 끄고 켜며(이 기기에만 저장), 고르지 않으면 기기의 '동작 줄이기' 설정을 따른다(`src/motion.tsx`, `<html data-motion>`).
- **시연·자동 확인용 표식**: 시연이 누를 입력칸·버튼에는 화면 동작과 상관없는 `data-demo="..."` 속성이 붙어 있다(예: `signup-email`, `child-submit`, `share-switch-jointPlay`, `coach-tried`). 확인 상자(`DangerAction`)는 `demo` 이름에 `-confirm`·`-cancel`을 붙여 확인·취소 버튼에 단다. 이름을 바꾸면 시연 각본도 함께 바꾼다.

| `frames.ts` | 장면 사진 뽑기. 영상 파일(`sampleFramesFromFile`: 처음·끝 5%를 뺀 구간에서 고르게 6장)과 실시간 카메라(`captureFrame`). 긴 변 512px 이하 JPEG, 한 장 300KB 이하·본문 전체 2MB 이하가 되도록 화질·크기를 낮춘다 |

| `AiConsentCard.tsx` | 아이별 동의 켜기·끄기(끄면 그 아이의 AI 관찰 기록이 모두 지워진다) |
| `ObservationCard.tsx` · `ObservationList.tsx` · `labels.ts` | 관찰 기록 한 건·목록, 태그 → 화면 문구 |
| `ai.css` | 위 화면의 스타일(`styles.css`의 색 변수만 쓴다. 고대비용 `--edge`는 없어도 되게 대체값을 둔다) |

지키는 것:

- **동의 없이는 한 장도 보내지 않는다.** 화면에서는 `GET /children/{id}/ai-consent`로 확인하고, 서버는 분석 토큰을 줄 때 다시 확인한다. `GET /policies`의 `aiObservationEnabled`가 `false`면 새로 만드는 화면(켜기, 촬영 버튼, 영상 기록 뒤의 관찰 기록 만들기)을 모두 숨긴다. 다만 이미 동의해 둔 아이는 그동안 쌓인 기록을 보고 지우거나 동의를 끌 수 있어야 하므로, 켜진 동의 카드와 목록은 남긴다(선생님 화면도 이미 있는 기록은 보여 준다).
- **사진은 `/ai/` 경로로만 간다.** `/api`에는 글자(영수증)만 보낸다. AI 서버에는 로그인 토큰이 아니라 분석 토큰만 보낸다. 사진·토큰·관찰 문장은 콘솔이나 브라우저 저장소에 남기지 않는다.
- **영상은 녹화·저장하지 않는다.** 실시간 카메라는 `audio: false`로 열고, 다 찍거나 멈추거나 화면을 떠나거나 가리면 모든 트랙을 멈춘다. 촬영 중에는 '지금 장면 사진을 찍고 있어요 (n/6)' 표시가 계속 보인다.
- **AI가 실패해도 지표 기록은 남는다.** 기록 화면에서는 지표 3개를 저장한 뒤에 관찰 기록을 만들고, 실패하면 안내와 '다시 시도'만 보여 준다.
- **촬영 전에 AI 서버를 확인한다.** `GET /ai/v1/health`(로그인 토큰 없이, `src/ai/health.ts`)의 `modelReady`가 `true`가 아니거나 닿지 않으면, 실시간 카메라 화면은 안내와 '다시 확인'을 보이고 '시작하기'를 막는다. 영상 기록 화면은 숫자 기록을 그대로 하게 두고, 사진을 뽑기 직전에 한 번 더 확인해 준비되지 않았으면 사진을 보내지 않고 '다시 확인하고 관찰 기록 만들기'를 보여 준다.
- **지운 관찰 기록의 카드**: AI 관찰 기록을 지우거나 동의를 끄면 서버가 그 기록으로 받은 코칭 카드도 지우므로, 아이 홈은 카드 목록을 다시 불러온다. 이미 지워진 카드에 '해봤어요'를 누르면(404) 목록에서 뺀다.
- 기관 선생님에게는 보호자가 '기관에서 촬영해 관찰 기록 남기기'를 켠 아이에만 촬영 버튼이 보인다.

저장 단계의 실패(`aiClient.ts`의 `save`):

| 서버 응답 | 하는 일 |
|---|---|
| 응답 없음, 502·503·504 | 같은 영수증으로 2번 더 보낸다. 그래도 안 되면 영수증을 실어 알리고, '다시 시도'는 저장만 다시 한다(분석 토큰을 새로 받지 않고 사진도 다시 보내지 않는다. 영수증을 받은 지 14분이 지나면 처음부터 다시 한다) |
| 429, 500, 503 `AI_UNAVAILABLE` | 바로 되풀이하지 않고 영수증을 실어 알린다(다시 시도 = 저장만) |
| 409 `DUPLICATE_REQUEST` | 앞선 요청이 저장된 것이다. 목록에서 방금 기록(과 가정 기록이면 함께 전달된 카드)을 찾아 성공으로 보여 준다. 찾지 못하면 실패가 아니라 '저장했어요' 안내를 보여 준다 |
| 400 `VALIDATION_FAILED` (촬영 시각을 보냈을 때) | 기기 시계가 서버보다 많이 빠른 경우다. 촬영 시각을 빼고 한 번 더 저장한다(서버 시각으로 저장) |
| 400 `AI_RECEIPT_INVALID`, 401, 403·404, 422 `AI_CONSENT_REQUIRED`, 그 밖의 4xx | 다시 보내도 같으므로 '다시 시도'를 보여 주지 않고, 이유에 맞는 문장으로 알린다 |

시험(`npm test`)은 DOM 없이 돈다. `frames.test.ts`는 `<video>`·`<canvas>`를 흉내 낸 가짜로 크기·화질 낮추기, 찾아가기 제한 시간, 멈춤과 ObjectURL 해제를 확인한다. 실제 카메라와 영상 디코딩은 실제 기기(안드로이드 크롬, iOS 사파리)에서 따로 확인해야 한다.

### 휴대폰으로 시험하기

실시간 카메라는 보안 연결이 필요해서 `http://192.168.x.x:5173` 같은 주소로는 켜지지 않는다(화면에 안내가 나온다). 개발 중에는 아래 가운데 하나를 쓴다.

- 안드로이드 + USB: `adb reverse tcp:5173 tcp:5173` 뒤 폰 크롬에서 `http://localhost:5173` (localhost라서 카메라가 켜진다).
- HTTPS 터널이나 배포 환경(HTTPS)에서 연다.
- 보안 연결이 없어도 **영상 기록하기** 화면의 '지금 촬영하기'(폰 카메라 앱으로 촬영)는 동작하고, 같은 영상에서 장면 사진을 뽑아 AI 관찰 기록을 만든다. 이 경로는 보안 연결에서만 있는 브라우저 기능(`crypto.randomUUID` 등)을 쓰지 않는다. `http://192.168.x.x:5173`으로 열려면 개발 서버를 `npm run dev -- --host`로 띄운다.

## 전체 흐름 보기 (시연 모드)

멘토·심사 시연용. 첫 화면의 **전체 흐름 보기 (시연용)** 버튼 또는 `/demo`에서 시작한다.

- 예시 기록은 영상 없이 넣은 숫자라 `modelVersion: demo-sample-data`로 저장된다. 영상 분석 단계에서는 직접 고른 영상을 기기 안에서 분석한다.

- 개발 서버(`npm run dev`)에서만 켜진다. 배포 빌드에서 쓰려면 `VITE_DEMO_MODE=true npm run build`.

## 기능별로 보기 (시연 모드)

기능 하나씩 동작 원리를 보여 주는 시연. 첫 화면의 **기능별로 보기 (시연용)** 버튼, `/demo` 화면 아래 **기능별로 보기**, 또는 `/demo/features`에서 고른다. 전체 흐름 보기와 같은 조건(`DEMO_ENABLED`: 개발 서버 또는 `VITE_DEMO_MODE=true`)에서만 켜진다. 코드는 `src/demo/features/`에 있다.

- **실제 화면을 움직인다**: 엔진(`runner.ts`)이 단계 목록을 차례로 실행하고, `domDriver.ts`가 실제 앱 화면을 조작한다. 글자는 네이티브 value setter + `input` 이벤트로 한 글자씩 넣어 React의 onChange가 그대로 돈다(초대 코드 칸처럼 화면이 고쳐 쓰는 값 위에 이어 쓴다). 체크박스·스위치·버튼은 `el.click()`, 달·날짜 칸은 '달력에서 골랐어요' 표시와 함께 한 번에 넣는다. 대상 요소는 `data-demo` 이름(`@이름`)이나 id(`#아이디`)로만 찾는다.
- **겉모습**: 대상 요소 비추기, 가짜 커서와 누름 물결, 화면 아래 패널의 말풍선(무엇을 넣는지, 어디로 가는지 — '이 기기 안에서 / 기록 서버로 / AI 서버로' 배지, 왜 그런지). 움직임 줄이기(`prefers-reduced-motion`)에서는 커서·물결 없이 칸을 한 번에 채우고 단계는 그대로 하나씩 보인다.
- **제어**: 일시정지/계속, 건너뛰기(지금 단계를 빨리 끝냄. 영상 분석 중이면 분석을 멈춤), 속도 1x/2x(이 기기에 기억), 그만 보기. 단계가 실패하면 '다시 해 보기 / 건너뛰고 계속'을 고른다. 시연 중 사람이 화면을 직접 누르거나 키를 치면 멈추고 '이어 보기 / 그만 보기'를 묻는다. 브라우저 뒤로·앞으로 가기를 하면 시연을 끝내고 정리한다.
- **서버로 간 내용**: 시연하는 동안에만 `api/client.ts`의 관찰 고리(`setApiObserver`)에 붙어 화면이 보낸 요청(메서드, 경로, 상태, JSON 본문과 응답)을 패널에 보인다. 비밀번호·토큰·영수증은 `••••`로, 장면 사진은 `[장면 사진 1장 · 약 NKB]`로 바꿔 담고, 파일 전송·장면 사진 수를 따로 센다. 시연 준비·화면 밖 확인 요청은 출처를 달아 함께 보인다. 기록은 그 탭 메모리에만 있다. `window.fetch`는 바꾸지 않으며, 시연이 아니면 관찰 고리는 비어 있다. 도움받기 시연의 '연결 실패'와 약관 다시 동의 시연의 '다시 동의할 약관' 응답은 이 고리로 흉내 내고, 패널에 '흉내'로 표시한다.
- **시연 계정**: 시나리오마다 필요한 만큼만 공개 API로 만든다(`session.ts`: 보호자 / +아이 / +예시 기록 / +선생님 / +연결·목표·메모). 이메일은 `@demo.hamkke.test`, 비밀번호는 임의 값. 끝나고 메뉴로 돌아가거나 그만 보기를 누르면 만든 계정을 모두 지운다(아이·기록은 계정과 함께 지워진다). 만든 계정은 그 탭의 sessionStorage에 적어 두어, 중간에 새로 고침해도 메뉴의 **모두 지우기**로 지울 수 있다. 실제 계정으로 로그인해 있으면 시작 전에 묻고, 그 토큰을 메모리에만 두었다가 끝나면 다시 그 계정으로 돌려놓는다(시연 도중 새로 고침하면 다시 로그인해야 한다). 전체 흐름 보기가 진행 중이면 먼저 끝내게 한다.
- **영상 기록 시연**은 `public/demo/sample-30s.mp4`가 있으면 그 샘플(사람이 나오지 않는 30초 시험 영상)을 파일 창 없이 넣는다. 없으면 사람이 직접 고르게 안내하고 기다린다. 샘플은 저장소 루트의 `test-videos/sample-30s.mp4`를 복사해 두면 되고, `*.mp4`는 git에서 제외되어 있다. 카메라를 켜는 버튼(`observe-camera-on`, `record-camera`)은 시연이 누르지 않는다.
- **시나리오**(`scenarios/`): 가입과 필수 약관 동의, 로그인(빈 칸·틀린 비밀번호 1회·성공), 아이 등록과 법정대리인 동의(동의 없이 보내면 서버도 거부), 약관 다시 동의(응답 흉내), 영상 기록(파일 전송 0건), 주간 기록 보기, 코칭 카드 '오늘 해봤어요', AI 관찰 기록 동의 켜고 끄기, 아이 정보 고치기, 기록 지우기, 공유 항목 켜고 끄기(선생님 쪽 응답 비교), 초대 코드로 연결(재사용 거절, 보호자 쪽 연결 해제), 선생님 목표·메모 → 보호자 화면, 초대 코드 취소, 선생님 연결 끊기, 실시간 카메라·기관 촬영 원리(설명형), 도움받기(로그아웃·연결 실패), 내 정보(동의 기록·비밀번호 바꾸기·내려받기·탈퇴). '새 서버 기능' 표시가 있는 시연은 기록 서버가 새 판이어야 끝까지 보인다.
- **표식 바꾸기**: 시나리오가 쓰는 `@이름`·`#아이디`가 화면 소스에 있는지 `scenarios.test.ts`가 정적으로 확인한다. 화면의 `data-demo`를 바꾸면 시나리오도 함께 바꾼다.

## 배포

`Dockerfile`(nginx, CSP·HSTS·본문 64KB 제한 포함)은 hamkke-api의 `deploy/docker-compose.yml`에서 함께 빌드된다.
nginx는 `/ai/`를 AI 서버(`AI_UPSTREAM`, 기본 `ai:8090`)로 넘긴다. 이 경로만 본문 2MB·읽기 제한 200초이고, 사진이 디스크에 닿지 않게 임시 파일을 쓰지 않는다. `/api/`와 나머지는 64KB 그대로다. AI 서버 주소는 요청할 때 Docker 내장 DNS(127.0.0.11)로 찾으므로 `ai` 서비스가 없어도 nginx는 뜬다(이 경로만 502).
배포 절차는 hamkke-api의 `docs/deploy.md`를 본다. nginx가 맨 앞단이라는 전제로 `X-Forwarded-For`를 실제 접속 주소(`$remote_addr`)로 덮어쓴다. nginx 앞에 다른 프록시를 두면 이 설정을 함께 손봐야 한다. 분석 모델(`public/mediapipe`)은 이미지 빌드 중 다시 받으므로 `.dockerignore`에서 뺀다.
